# PAR ORDO PRO — BONUS V1 · бонусный счёт 3% на браслете

Бонус гостя теперь можно не только копить, но и тратить прямо на браслете.

- **Накопление.** С любой оплаченной суммы гостя (входы и товары) 3% идёт на бонусный счёт.
  Пример: чек 1 000 сом → +30 сом. Бонус за текущий визит начисляется после его завершения.
- **Списание.** Сотрудник открывает браслет гостя и у неоплаченной позиции нажимает
  **«🎁 Оплатить бонусом»**. Сумма снимается со счёта автоматически.
- **Остаток.** Если бонуса больше цены, остаток остаётся на счёте и копится дальше. Если бонуса
  меньше цены, бонус покрывает часть, а остаток гость доплачивает наличными или переводом.

## Как работает на браслете

1. Гость должен быть привязан к Базе клиентов («Постоянный клиент»). Если гость не привязан,
   вместо счёта видна подсказка: «Привяжите гостя — 3% с этого чека уйдут на его бонусный счёт».
2. В блоке гостя показан **«Бонусный счёт · 3%»**: доступно сейчас, накоплено, списано,
   сколько начислится за этот визит.
3. У каждой неоплаченной позиции есть кнопка **«🎁 Оплатить бонусом»** с подсказкой, например
   «спишется 120 из 220 сом» или «бонус 100 сом · доплата 100».
4. После нажатия открывается окно подтверждения: цена, сколько списать с бонуса, сколько доплатить,
   баланс «220 → 100». Кнопка «🎁 Списать 120 сом бонусом» — и позиция оплачена.
5. Оплаченная бонусом позиция подсвечена золотом: «🎁 Бонусом · 120 сом» и кнопка «Отменить».
   «Отменить» возвращает бонус на счёт, позиция снова «Ожидает оплаты».

Правила защиты:

- Бонусом оплачивается только неоплаченная позиция. Если позиция уже отмечена «наличными» или
  «переводом», сначала поставьте «Ожидает оплаты».
- У позиции, оплаченной бонусом, нельзя менять количество, цену и способ оплаты — сначала «Отменить».
- С браслета нельзя снять или сменить клиента, пока на нём есть оплата бонусом этого клиента.
- Браслет руководителя №3 бесплатный, кнопки бонуса там нет.
- Тратить бонус могут администратор и сотрудник смены. Руководитель видит счёт без кнопок.
- Если сервер не сохранил оплату, позиция возвращается как была и показывается ошибка.

Акция «5-й вход бесплатно» заменена бонусом 3%: её счётчик на браслете больше не показывается.
Если у гостя бесплатный вход уже был активирован раньше, кнопка остаётся, и его можно применить.

## Где ещё виден бонус

- **База клиентов**: у каждого гостя «Доступно сейчас», в карточке «Накоплено · 3% × сумма»,
  «Оплачено бонусом». Плитка «сом бонусов на счетах», вкладка «Топ по бонусу».
- **Ежедневный отчёт**: строка «Оплачено бонусом 3%» за оба дня. Товар, выданный за бонус, идёт без
  выручки, но его закуп учитывается в прибыли, с пометкой «за бонус».
- **Статистика товаров**: проданные за бонус штуки входят в скорость продаж товара.
- **История клиентов**: строка «🎁 бонус 70» у позиции вместо «Наличные».

## Как хранится списание (Worker не нужно менять)

Списание записывается в саму позицию чека и сохраняется обычным сохранением браслета
(`PUT /api/admin/control/clients/:id`):

| Поле | Пример | Смысл |
|---|---|---|
| `name` | `Жарма · бонус 120` | метка «· бонус N» в названии |
| `price` | `0` (или остаток за штуку) | цена уменьшена на сумму бонуса |
| `method` | `cash` при полной оплате бонусом, иначе `pending` до доплаты | |
| `bonusPaid` | `120` | сколько сом покрыл бонус |
| `bonusBasePrice`, `bonusBaseName` | `120`, `Жарма` | цена и название до бонуса |
| `bonusCustomerId` | `cust5` | с чьего счёта списано |
| `bonusAt`, `bonusBy`, `bonusRate` | время, сотрудник, `0.03` | для проверки |

- Касса и выручка честные: бонус — не деньги, поэтому цена позиции уменьшается, а «Всего оплачено»
  гостя растёт только на реально оплаченную сумму. С бонуса бонус не начисляется.
- **Баланс = накоплено − сумма всех позиций гостя с меткой бонуса** по визитам и по отчётам смен.
  Отдельной «копилки» нет. Удалили или отменили позицию — бонус сам вернулся на счёт.
- Если Worker не сохранит дополнительные поля, списание всё равно распознаётся по метке
  «· бонус N» в названии. Проверено тестом, где сервер удаляет все лишние поля.
- При количестве больше 1 цена за штуку остаётся целой: 2 × 120 и бонус 45 → 2 × 98 = 196 к оплате,
  44 сом бонусом, 1 сом остаётся на счёте.

## PAR ORDO GO

Код приложения PAR ORDO GO (клиентское приложение с картой «Бонус: 5-й вход бесплатно 0/5») не
входит в этот репозиторий, поэтому GO в этот пакет не вошёл. Чтобы в GO был тот же счёт, GO должен
показывать то же число, что PRO:

```
накоплено = floor(0.03 × сумма всех завершённых визитов гостя)   // как «Всего оплачено» в PRO
списано   = сумма bonusPaid всех позиций гостя (или N из метки «· бонус N» в названии)
доступно  = накоплено − списано
```

Лучше считать это в Worker, в ответе для GO, одним полем (например `bonusBalance`), чтобы PRO и GO
брали одно число. Если GO-аккаунт не связан с Базой клиентов, свяжите визиты GO с клиентом базы
(`customerBaseId`) — иначе бонусы GO-визитов и браслетов будут на разных счетах.

## Проверено

Playwright (мобильный 390 px и ПК 1280 px, обычный режим и `prefers-reduced-motion`):

- полная оплата бонусом, частичная (2 × 100 при бонусе 100), «бонуса пока нет», отмена;
- защита: количество, цена, способ оплаты, снятие клиента с браслета;
- сервер без дополнительных полей (только метка в названии): баланс, отмена и повторное списание;
- ошибка сервера при сохранении: позиция вернулась, понятное сообщение;
- База клиентов, Ежедневный отчёт, Статистика товаров, История — без ошибок в консоли;
- регрессия INNER/TWIN/SECTIONS без ошибок.

## Как отключить

Удалить две строки `par-ordo-bonus-v1.*` из `index.html`. Уже сделанные списания останутся в чеках
(метка «· бонус N» в названии, цена со скидкой).
